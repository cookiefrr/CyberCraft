# Development and testing

The project uses Java 21, NeoForge 21.1.264, ModDevGradle 2.0.148, Gradle 9.2.1, and GeckoLib 4.9.3. Versions are pinned in the build and properties files. GeckoLib is resolved from its official Maven repository and remains a separate installation dependency.

## Reproducible resources

`./gradlew runData` runs the recipe, gameplay, asset, and English language providers. Their output is tracked in `src/generated/resources`; edit providers instead of generated JSON. Run generation again and inspect the diff before committing. Textures remain authored resources under `src/main/resources`.

The generated GUI perspective uses GeckoLib's item-renderer integration to draw the original flat icon. Held/dropped and equipped views use the native 3D geometry. GeckoLib does not drive combat or body animations.

`ImplantModels` is the source of truth for 3D geometry: groups carry a bone, a pivot, and cuboids in humanoid model pixels (1 px = 1/16 block). `AssetData` emits an auto-fitted `_3d` item model only. Worn geometry is drawn directly by `ImplantRenderer` from the shared 256×256 `textures/item/cyberware_palette.png` atlas, so no `_worn_*` models or per-implant textures exist; `cyberware_palette_e.png` is the shader-only emissive companion. Animation clips live in `ImplantAnimations`. The palette atlas is generated by `tools/gen-cyberware-palette.js` and the Mantis atlas by `tools/gen-mantis-texture.js`. Regenerate the scripts' output when changing colours, then run `runData`:

```sh
node tools/gen-cyberware-palette.js src/main/resources/assets/cybercraft/textures/item/cyberware_palette.png
node tools/gen-mantis-texture.js src/main/resources/assets/cybercraft/textures/item/mantis_blade.png
```

## Automated checks

```sh
./gradlew runData
./gradlew test
./gradlew runGameTestServer
./gradlew clean build
```

- `src/test`: progression boundaries and resource completeness checks.
- `src/gametest`: independent test mod, fixtures, synthetic players, inventories, mobs, and circuitry.
- `run-gametest`: disposable server world and logs; never uses a player save.
- `build/reports/tests/test`: unit-test report.

The test mod is loaded only by the GameTest run and is excluded from the published jar. Tests cover installed access requirements, inventory/full-inventory transactions, named components, death copying, saved cooldowns, damage bonuses, retaliation, effect ownership, added/missing definitions, protected targets, block access, redstone output/propagation/expiry, persistence encoding, animation clip evaluation/catalogue completeness, payload round-trip, trigger dispatch, and Self-ICE cancellation.

GameTests run on a real NeoForge server with GeckoLib installed. Normal upstream development warnings about resource URLs, command ambiguities, or GeckoLib's development refmap are not mod failures.

## Manual client review

`./gradlew runClient` starts the development client. Use a fresh world. Verify the CW tab in survival and creative, Back navigation and selected creative category, GUI scales, Shift tooltips, ordinary clicks/dragging, scanner targets, first-/third-person implant placement, idle/active animations, and trigger clips (attack, damage, kill, hack, landing, Self-ICE). Check armor and both player arm widths. The user performs visual acceptance; automated checks do not establish visual quality.

`./gradlew runServer` starts a normal dedicated server. Keep world saves, server configuration, logs, third-party mods, IDE metadata, and local tools out of commits.

## Branches

Publish development commits to `indev`; `main` remains the stable branch. Do not force-push or publish unverified changes. Keep the README short; put implementation and extension details in these guides.
